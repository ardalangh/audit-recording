Summary

Saving the profile is the slowest and least clear moment in the flow. After the tap, nothing on screen changes for 1.5 s; then a toast confirms with a different name for the thing just saved. The settings list uses that second name too. The helper text under the form is very faint, and the tab bar is icons only. The demo app is synthetic and its issues were planted to show what the skill reports.

  1. Show a pressed state on Save at once and a "Saving…" state after 100 ms (F-01).
  2. Call it "Profile" everywhere: title, toast and Settings row (F-02).
  3. Darken the helper text to the label colour or darker (F-03).

P1 · MajorHigh confidence

Save gives no feedback for 1.5 s F-01

00:01.000-00:02.533 Profile

What the recording shows
`measure` from the touch at 00:01.000: first visible change +1533 ms (the toast). Nothing in the window changed before that; the button has no pressed or busy state. Timing resolution ±33 ms.
Expected
Visible feedback within 100 ms of a tap, and a progress state for any wait over about 1 s.
Cost to the user
The tap looks ignored, so people tap again (double submits) or leave before the save lands.
Likely cause (inferred)
The Save button has no :active or busy style (seen in the code).

Suggested fix

Darken Save on press, then switch it to a disabled "Saving…" state with a spinner until the request returns.

Where in the code

  • docs/demo/app/index.html:43 the Save button: no pressed or busy state
Details

NowNo change
Change toPressed, then "Saving…" with spinner, disabled
  1. Add an :active style (darker, 98% scale).
  2. On submit, disable the button and show "Saving…" with a spinner after 100 ms.
  3. Restore it when the request finishes or fails.
Effort SLAT-FEEDBACK

Check it worked: Re-record with show-touches on and run `measure`: first change within 100 ms of the tap.

P3 · PolishHigh confidence

Helper text under the form is barely visible F-03

What the recording shows
The line "Your name and bio are shown on notes you share." is ~12 pt light grey on the beige background. From video it looks well below 4.5:1; the code confirms #cfcac3 on #f6f3ee, 1.47:1.

The one sentence that says the bio is public is the hardest to read, so people share details they meant to keep private.

P3 · PolishMedium confidence

Tab bar icons have no labels F-04

00:04.633-00:07.600 Settings

What the recording shows
The tab bar shows four glyphs with no text. Inactive icons are light grey (#9c958c on white, 2.96:1 per the code).
Expected
iOS tab bars pair each icon with a short label; icons that are UI components need 3:1.
Cost to the user
People have to guess what the pencil and magnifier open, and the faint icons are hard to see in sunlight.

Suggested fix

Add a one-word label under each icon and darken inactive icons.
